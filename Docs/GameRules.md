# game-VR-BeatSync 게임 규칙 & 진행상황

> VR 비트세이버 스타일 리듬게임 (Unity 6.6 / XR Interaction Toolkit 3.x)
> 이 문서는 **게임의 방향(규칙)** 을 글로 명확히 하기 위한 기준 문서입니다.
> 기능을 추가·수정할 때는 이 문서를 먼저 확인하고, 바뀐 내용은 이 문서에도 반영합니다.

---

## 1. 프로토콜 (게임 규칙)

### 1-1. 핵심 목표
- 노트는 **노래의 비트(비트맵)에 맞춰** 나온다. (랜덤 생성 X)
- 비트맵은 **Beat Sage** 에서 받은 파일을 사용한다.
  - `.dat` → `.json` 으로 확장자만 바꿔서 Unity TextAsset 으로 사용 (내용은 원본 그대로)
  - Beat Sage 옵션: Standard + 난이도 선택. (90 Degrees / Bombs / Obstacles / Dot Blocks 는 해당 기능을 만들기 전까지 끔)
- 나중에 **장애물(Obstacles)** 도 비트맵에 맞춰 나오게 한다.

### 1-2. 게임 흐름 (모든 노래 공통 패턴)

```
[노래 선택 (토글 목록)]
        ↓
[대기] 시작 버튼 보임 / 카운트다운 텍스트 꺼짐(SetActive false)
        ↓  시작 버튼 누름
[카운트다운] 시작 버튼 꺼짐 / 카운트다운 텍스트 켜짐 → 3, 2, 1, GO!
        ↓  카운트다운 끝
[플레이] 카운트다운 텍스트 꺼짐 / 비트에 맞춰 노트 생성 / 노래 재생
         화면에 Combo, Miss 표시
        ↓  레벨 오를 때 (또는 노래 끝)
[결과 패널] 레벨, Combo, Miss 표시
         ├─ [다시 하기] → 같은 노래로 카운트다운부터 다시
         └─ [노래 선택] → 토글 목록에서 다른 노래 선택 → 카운트다운부터 같은 패턴
```

### 1-3. 상태별 규칙

| 상태 | 시작 버튼 | 카운트다운 텍스트 | 노트 | 노래 | 결과 패널 |
|---|---|---|---|---|---|
| 노래 선택 | - | 꺼짐 | 없음 | 정지 | 꺼짐 |
| 대기 | **보임** | **꺼짐** | 없음 | 정지 | 꺼짐 |
| 카운트다운 | **꺼짐** | **켜짐** (3,2,1,GO) | 없음 | 정지 | 꺼짐 |
| 플레이 | 꺼짐 | **꺼짐** | **비트에 맞춰 생성** | 재생 | 꺼짐 |
| 결과 | 꺼짐 | 꺼짐 | 정지/정리 | 정지 | **보임** |

- 노래 AudioSource 는 **Play On Awake 끔**, GM 이 직접 재생한다.
- 노래 / 비트맵이 바뀌어도 흐름은 **항상 같다** (노래 선택 → 대기 → 카운트다운 → 플레이 → 결과).

### 1-4. 플레이 중 표시
- **Combo**: 연속으로 벤 노트 수
- **Miss**: 놓친 노트 수 (못 베고 지나간 노트)
- **레벨**: (규칙 정리 필요 — 아래 "결정할 것" 참고)

### 1-5. 결과 패널
- 표시: **레벨, Combo, Miss**
- 버튼:
  - **다시 하기**: 같은 노래를 카운트다운부터 다시 플레이
  - **노래 선택**: 노래 목록 토글로 돌아가 다른 노래 선택 → 같은 패턴으로 플레이

### 1-6. 노래 선택
- 노래 목록은 **토글(Toggle)** 로 선택한다.
- 노래 하나 = **AudioClip + 비트맵(json) + BPM** 묶음.
- 다른 노래도 똑같이: 카운트다운 → 비트에 맞춰 노트 → 결과 패널.

### 1-7. 결정할 것 (아직 정해지지 않음)
- [ ] **레벨**이 무엇인지: 플레이 중 점수/콤보로 오르는 레벨? 난이도(Normal~Expert+)? 스테이지(노래 순서)?
- [ ] **레벨이 오를 때** 결과 패널이 뜨면 게임이 멈추는지(일시정지 후 재개), 노래 끝에 한 번만 뜨는지
- [ ] "재개" 버튼이 필요한지 (일시정지 → 이어하기)
- [ ] Miss 판정 기준 (노트가 플레이어를 지나간 순간? 일정 거리?)
- [ ] 장애물을 피하지 못했을 때 벌점 (Miss 증가? Combo 끊김? 체력 감소?)
- [ ] 폭탄(Bombs) 사용 여부

## 3. 작업 규칙 (코드 작성 시)
- 요청하지 않은 수정은 하지 않는다. 설명만 요청하면 설명만 한다.
- 하이어라키/씬 수정이 필요하면 직접 하지 않고 **방법을 알려준다**.
- 중괄호는 K&R 스타일 (`{` 는 항상 같은 줄, 클래스·메서드 포함).
- `_이름` 은 **private 변수에만** 사용한다.
- 단일 책임 원칙(SRP) 을 기준으로 클래스를 나눈다.
